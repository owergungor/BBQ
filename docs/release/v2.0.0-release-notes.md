# BBQ v2.0.0 Release Notes — Production Desktop Productivity Island

BBQ v2.0.0 is the official General Availability (GA) release of the lightweight, cross-platform desktop productivity island built with Tauri 2 and Rust.

---

## Key Capabilities & Features

### 1. Dynamic Island-Style Desktop HUD
- Unobtrusive, ambient status pill anchored at the top of the screen that smoothly expands into interactive widgets.
- Hardware-accelerated UI built with zero runtime layout thrash.
- Responds gracefully to multi-monitor arrangements, heterogeneous DPI transitions, and dynamic display additions/removals.

### 2. Comprehensive Productivity Widget Suite
- **Quick Launcher**: Fuzzy application and command search with keyboard navigation and bounded history.
- **Timer & Pomodoro**: State-driven countdown, stopwatch, and Pomodoro timers with accurate timestamp diffing, interval-based work/break cycles, and system audio/notification alerts.
- **Reminders**: Due-date notification scheduling with bounded startup replay of overdue items and robust cancellation lifecycles.
- **Clipboard History**: Privacy-first clipboard capture with duplicate suppression, configurable retention budgets (FIFO up to 100 entries), and explicit purge controls.
- **Media Controls**: Real-time playback status display (title, artist, album art, play/pause, next/previous tracks) interfacing directly with native OS media subsystems.
- **Drop Shelf**: Quick-staging area for files and paths dragged from the file manager with capacity bounds.
- **File Workspace**: Pinned files and directories for instant access, direct file revealing in native file explorers, and quick launches.
- **System Indicators**: Real-time CPU, RAM, battery, and network status display powered by native hardware metrics collectors.
- **Settings & Customization**: Dynamic theme switcher (Dark, Light, System), 11 curated accent palettes, custom HEX color picker, configurable dimensions, and interactive hotkey recorder.

## Architectural & Engineering Highlights

- **Zero-Polling Policy**: Strict prohibition against `setInterval`, continuous `requestAnimationFrame` loops, and recursive `setTimeout` polling. All updates are driven strictly by native push events, OS hooks, or bounded timer wakeups.
- **Bounded Resource Budgets**: Enforces <= 60 MB working set RAM target (~46 MB typical baseline) and ~0% idle CPU consumption.
- **Local Storage Reliability**: Local SQLite 3 database operating in WAL mode with synchronous NORMAL, defensive schema migrations, automatic corruption detection, and quarantined recovery. Note: Database is stored locally in unencrypted standard SQLite WAL files.
- **Single-Instance Forwarding**: IPC socket forwarding ensures only one instance runs per user session, gracefully bringing the running window to front on repeated execution.
- **Accessibility & Motion**: WCAG 2.1 AA contrast compliance across all themes, polite `aria-live` screen-reader feedback on actions, and strict respect for operating system `prefers-reduced-motion` settings.

## Cross-Platform Parity & Known Platform Limitations

BBQ supports Windows 10/11, macOS 12+, and Linux (X11 & Wayland) through a unified `PlatformCapabilities` contract:

- **Windows 10/11 (Fullest Native Integration)**:
  - Global hotkeys, Windows Clipboard Viewer APIs, System Media Transport Controls (SMTC), Windows Toast Notifications, and DPI-aware absolute window positioning are fully supported natively.
- **macOS (12+)**:
  - Global hotkeys, native pasteboard change count polling thread, and `NSUserNotification` are supported.
  - Media controls interact with Apple Music and Spotify via AppleScript/Automation and may require explicit user permission in System Settings.
  - Media timeline scrubbing and position seeking are not universally available across all third-party media players.
- **Linux (X11 & Wayland)**:
  - FreeDesktop Notifications (`org.freedesktop.Notifications`) and MPRIS2 (`org.mpris.MediaPlayer2`) media integration are fully supported via asynchronous D-Bus IPC.
  - Under X11, global hotkeys (`XGrabKey`) and absolute window positioning are fully supported.
  - Under Wayland, absolute window positioning is compositor-dependent; compositors that restrict client placement (e.g. strict GNOME Wayland) determine window anchoring according to shell policies.
  - Global hotkeys on Wayland depend on compositor XDG desktop portal support (`org.freedesktop.portal.GlobalShortcuts`).
